# Project Charter
## Corporate Back-Office Administration System

### 1. Project Overview

**Project Name:** Corporate Back-Office Administration System

**Organization:** ABC Enterprise Sdn. Bhd.

**Project Role:** Project Management Analyst / System Analyst

**Project Methodology:** Agile / Scrum

**Project Duration:** 12 Weeks

---

### 2. Business Problem

The organization currently relies on multiple spreadsheets and manual processes to manage customer and operational information.

This creates several challenges, including:

- Duplicate or inconsistent data
- Time-consuming manual processes
- Limited visibility of operational information
- Difficulty generating management reports
- Increased risk of human error

A centralized back-office administration system is proposed to improve operational efficiency and provide stakeholders with a single source of information.

---

### 3. Project Objectives

The project aims to:

1. Develop a centralized back-office administration system.
2. Improve visibility of operational information for business stakeholders.
3. Reduce reliance on manual spreadsheet-based processes.
4. Provide standardized reporting capabilities.
5. Improve data accuracy and consistency.
6. Implement role-based access for system users.

---

### 4. Project Scope

#### In Scope

- User authentication and access control
- Customer record management
- Administrative functions
- Operational reporting
- User management
- Audit/activity tracking
- API integration
- User Acceptance Testing (UAT)
- Production deployment

#### Out of Scope

- Mobile application development
- Third-party payment processing
- Advanced analytics and machine learning
- Customer-facing web portal

---

### 5. Key Stakeholders

| Stakeholder | Responsibility |
|---|---|
| Project Sponsor | Project direction and approval |
| Business Stakeholders | Business requirements and UAT |
| Project Manager | Project planning and delivery |
| Project Management Analyst | Project coordination and tracking |
| System Analyst | Requirements and system analysis |
| Developers | System development |
| QA Team | Testing and defect validation |
| External Vendors | Integration/deployment support |

---

### 6. Key Deliverables

- Business and system requirements
- System process flows
- Back-office administration system
- API integration
- Test cases and test results
- UAT documentation
- User documentation
- Deployment plan
- Production release

---

### 7. Success Criteria

The project will be considered successful when:

- All agreed in-scope requirements are implemented.
- Critical and high-priority defects are resolved before production release.
- Business stakeholders successfully complete UAT.
- Required stakeholders approve the production deployment.
- The system is successfully deployed to the production environment.
- Required project documentation is completed and approved.

---

### 8. Key Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Requirement changes | High | Establish change request process |
| Development delays | High | Monitor sprint progress and dependencies |
| UAT delays | Medium | Schedule UAT early and confirm stakeholder availability |
| Integration issues | High | Conduct API testing before UAT |
| Deployment issues | High | Prepare deployment and rollback plans |

---

### 9. Project Constraints

- Fixed project timeline
- Limited development resources
- Stakeholder availability
- Dependency on external vendors
- Requirement changes during development

---

### 10. Project Outcome

The expected outcome is a centralized back-office administration system that improves operational visibility, reduces manual administrative work, and provides stakeholders with reliable access to operational information and reports.
